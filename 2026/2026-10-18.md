# 2026-10-18

*(컨트롤 노드 카드 재설치 3: 노트북 첫 부팅과 마무리, 10-16 부터 이어진 작업)*

## 작업

- 카드와 백업 USB 를 홈 서버에서 빼고 노트북 첫 부팅을 진행함. 설정과 프로필 설치를 마친 뒤 FIDO2 토큰 등록으로 넘어감
- 토큰 등록 스크립트가 두 번째 토큰을 세지 못해 같은 파티션에 등록을 되풀이함. 원인은 luksDump 가 systemd 토큰 플러그인을 읽은 뒤부터 출력을 stderr 로 보내는 것으로, 시험용 LUKS2 이미지로 재현하고 JSON 메타데이터로 세게 고침. 그 자리에서는 사용자가 토큰 슬롯을 지우고 손으로 다시 등록해 두 토큰이 모두 열리는 것과 재부팅 잠금 해제를 확인함
- 지운 등록이 토큰 안에도 남는지 확인함. systemd 는 자격 증명을 토큰에 저장하지 않는 방식으로 등록하므로 지울 것이 없음
- 고친 것 넷을 패치 묶음과 인계 문서로 컨트롤 노드에 넘겨, 거기서 사용자가 고른 FIDO2 토큰 SSH 서명으로 커밋하고 올림. 홈 서버에서 서명과 트리가 원본과 같은지 대조하고, 할 일 장부 항목을 끝냄. 다 쓴 임시 클론과 로그는 사용자 확인을 받아 지움
- 컨트롤 노드에서 프린터 프로필을 깔아 보니 방화벽의 mDNS 규칙이 파일에만 들어가고 바로 적용되지 않음. 원인은 nftables 유닛이 실행하고 끝나는 방식이라 늘 꺼진 것으로 보여 스크립트가 다시 읽기를 건너뛴 것으로, 유닛 정의로 확인하고 고치는 방법을 컨트롤 노드 세션에 넘겼고, 그쪽에서 고쳐 올림

## AI 활용

- Claude Code(Opus 5.5) 세션이 노트북 화면을 볼 수 없어, 사용자가 알려 준 증상을 홈 서버에서 같은 버전의 도구와 시험용 이미지로 재현해 원인을 찾음
- 토큰이 노트북으로 돌아가 홈 서버의 임시 서명 기간이 끝난 것을 같은 서버의 다른 세션들에 알림
- 컨트롤 노드의 Claude Code 세션과 세션 간 메시지로 인계를 주고받음. 그쪽 세션이 인계 문서의 서명 방법이 실제 저장소 설정과 맞지 않는 것을 짚었고, 사용자가 서명 방법을 정함. 백업 USB 의 내용과 지울 시점에 대한 그쪽 질문에도 답함
- 아쉬운 점: 인계 문서에 서명 방법을 홈 서버 설정에서 짐작해 적었음. 프린터 프로필의 방화벽 다시 읽기를 유닛 정의를 보지 않고 짐작으로 짰음
