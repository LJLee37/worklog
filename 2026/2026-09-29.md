# 2026-09-29

*(메인 서버 - 개인 비서의 대화 모델 교체 검토)*

## 작업

- 비용 때문에 줄여 둔 개인 비서의 컨텍스트 윈도우(대화 압축 상한)를 올렸다. 줄인 뒤 시스템 프롬프트와 기억이 커져 압축 직후 크기가 이미 상한을 넘었고, 거의 매 턴 압축이 돌며 대화를 잘라 내고 있었다. 메인 서버 라이브 설정만 임시로 올렸고 정식 반영은 컨트롤 노드로 넘겼다.
- 대화 모델을 비-중국산으로 바꿀 후보를 찾았다. 지금 쓰는 공급자 안에는 쓸 만한 후보가 없어서 다른 공급자들의 API 와 구독 요금, 제3자 에이전트 허용 정책을 조사하고 월 비용을 비교했다.
- 기존 평가 도구에 다른 공급자의 API 경로를 붙여, 지금 쓰는 모델과 새 후보들을 22개 장면으로 돌렸다. 도구 사용과 규칙은 기계로 검사했고, 추론 강도(low, medium, high)는 대화에서 비용과 품질 모두 거의 차이가 없었다.
- 후보 15개를 이름을 가린 채 직접 채점하는 페이지를 만들어 8개 장면을 채점했다(답마다 1~5점, 좋은 답은 여러 개 표시).
- 내 점수에서 채점 기준을 역추정하고, AI 채점자(Sonnet, Opus, Fable)가 내 점수와 얼마나 맞는지 검증한 뒤 Opus 로 약 1,000개 답을 채점했다.
- 일부 후보가 인격 설정의 "짧게 답하라" 규칙을 그대로 지켜 답이 얇다는 것을 확인하고, 규칙을 풀어 다시 시험했다.

## AI 활용

- Claude Code(Opus 5.5)로 진행했다. 채점 기준은 메인 세션과 Fable 서브에이전트가 따로 뽑아 교차 확인했고, 채점과 검증은 Sonnet, Opus, Fable 서브에이전트를 병렬로 돌렸다.
- 평가 대상 모델을 부르는 API 키 두 개를 따로 만들어 썼다.
- 아쉬웠던 점: 첫 채점 자료에 비서가 받은 기억 정보를 빠뜨려, 채점자가 실제 기억에 있는 사정을 지어낸 것으로 깎았다. 검증에서 드러나 고쳤다.
