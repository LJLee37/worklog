## 작업

- 개인 비서의 대화, 예약 작업, 보조 작업을 전날 평가한 가벼운 모델로 옮겨 하루 동안 시험했다. 이 모델은 프롬프트가 10만 토큰을 넘으면 단가가 다섯 배가 되므로, 대화 압축이 그 아래에서 걸리게 맞췄다. 처음에는 압축 기준을 잘못 계산해 11만 토큰대에서 압축이 걸렸고, 실제 로그로 계산 방식을 확인해 고쳤다.
- 모델을 바꾸자 웹 검색이 실패했다. 쓰던 검색이 특정 공급자의 모델에서만 동작하는 방식이었다. 검색은 서버에서 직접 하는 라이브러리로 바꾸고 헤드리스 브라우저를 설치했다(시스템 라이브러리는 사용자가 설치). 페이지 본문 추출은 외부 서비스 없이 서버에서 하는 플러그인을 새로 만들었다. 정적 페이지는 HTTP로 받아 본문만 남기고, 스크립트로 그리는 페이지는 헤드리스 브라우저로 연 뒤 읽는다. 리디렉트마다 내부망 주소를 막는다.
- 브라우저 결과와 길어진 세션 요약 때문에 압축 뒤에도 대화가 기준 바로 밑에 머물러, 거의 매 턴 1분 넘게 압축하는 문제가 생겼다. 결과 크기 상한, 압축 때 남기는 최근 메시지 수, 오래된 도구 결과 정리 설정을 조정했고, 마지막에는 새 세션으로 시작했다. 새 세션의 시작 크기는 약 2만 8천 토큰이고 턴당 비용은 약 0.4센트였다.
- 기존 AI 구독을 환불받고 주 모델을 정식으로 바꿨다. 손으로 고친 설정은 컨트롤 노드 세션이 Ansible 템플릿으로 옮겨 두 노드에 적용했다. 요금제에 딸린 월간 API 크레딧이 비서 사용분에 쓰이는 것도 시험 메시지로 확인했다.
- 더 큰 두 모델의 비용을 실측 사용 패턴으로 계산했다. 대화에 쓰기에는 크레딧을 넘어서, 하루 한 번 도는 저녁 소식 작업만 중간급 모델로 시험했다. 결과는 비슷했고 비용은 열 배 이상이라 되돌렸다.
- 비서가 터미널에서 패키지를 설치하다 비서 프로그램 자체의 파이썬 환경에 패키지가 들어간 것을 찾았다. 실행 경로 순서 때문이었다. 검증 명령이 시스템 파이썬을 쓰도록 스킬을 고치고(컨트롤 노드), 들어간 패키지를 지웠다.
- 비서가 지식 저장소에 넣은 불필요한 문구를 빼고, 같은 일이 반복되지 않게 노트 머리말에 규칙을 더했다. 저장소 CI가 수정 시각을 검사하므로 되돌리기 커밋 대신 손으로 고쳐 커밋했다.
- 저녁 할 일 알림이 할 일 메모의 배경 문구를 현재 사실처럼 옮긴 것을 찾아 메모를 고쳤다. 메모를 JSON 없이 볼 수 있는 출력은 장부 작업 세션에 요청했다.
- 비서 프로그램의 새 안정판을 검토했다. 운영 설치와 분리한 사본으로 우리가 쓰는 설정과 플러그인 API를 대조했고, 컨트롤 노드에 인계해 두 노드를 올렸다.
- 도구를 쓰는 턴마다 캐시를 일부 다시 쓰는 원인을 찾았다. 비서 프로그램이 가장 최근 응답의 추론 블록만 남기고 앞의 것은 지우기 때문이었다.
- 비서 시스템을 공개 배포하려는 구상에 쓸 자료(설치 경로, 모델별 비용, 운영하며 배운 함정)를 문서로 모았다.
