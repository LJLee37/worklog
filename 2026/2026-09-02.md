### 오후 세션 — driftline M1 착수 (계획 평가 + 구현)

#### 작업

- `docs/M1.md` 계획을 먼저 평가: 방향은 유지하되 "결정"으로만 적혀 있던 항목(상태
  해시 알고리즘, 오버플로 정책, ECS 선택, 시간 상수·1년 일수, CI 구조, 타깃 간 해시
  검증 방법, 기본 데이터 파일 위치)을 실제 결정으로 채우고, 0절의 오류("툴체인 없음"
  문구 위치, PATH 문제는 이미 해결돼 있었음)와 개발 노드 제약(헤드리스, 4 GB)을 반영해
  문서를 보완한 뒤 그대로 실행.
- 개발 환경: `rust-toolchain.toml`을 `1.98.0`으로 핀 고정하고 6개 크로스 타깃 설치.
  프로젝트 위치(외장 디스크 vs `~/gitRepos`)는 사용자 결정으로 남김.
- `driftline-core` 구현(결정론 인프라 → 시뮬 골격 순):
  - fixed-point `Fx`(Q31.32): 연산은 포화, `* / sqrt`는 floor. 128비트 정수로 직접
    계산해 `fixed` 크레이트 동작에 의존하지 않고, 규칙을 유닛/프로퍼티 테스트로 고정.
  - FNV-1a 64 상태 해시 + 명시적 little-endian 인코딩 트레이트, PCG32 RNG(레퍼런스
    벡터 검증) + 시스템별 스트림, 시간/달력/낮·밤(20 tick/분, 60일 1년), 시드 기반
    바다 수심 맵(정수 value noise), RON 시나리오 스키마, 배(갑판 스택·타일)·폰,
    `World` 스냅샷(serde) + 고정 순서 스케줄러 + tick 루프, 입력 로그·리플레이 러너.
  - 정수 오버플로는 모든 프로파일에서 panic 되도록 `overflow-checks = true`.
- 리플레이 하네스: `tools/replay` CLI(verify/run/update/new), 픽스처 2개
  (`tests/replays/`, 골든 해시 + 체크포인트), core 통합 테스트. 골든 갱신 리뷰 절차 문서화.
- `driftline-server`: 헤드리스 러너(시드·시나리오·tick 수, 하루마다 해시 출력, 스냅샷
  저장). release로 200k tick 실행해 안정 확인.
- `driftline-client`: winit 0.30 + wgpu 30 창, 인스턴스 컬러 쿼드 파이프라인, 활성 층
  탑다운 타일·폰·침로 마커·시각 바, 고정 timestep 누적기, 일시정지/속도/층/줌 키.
  개발 노드가 헤드리스라 빌드·clippy까지만 확인(육안 확인은 데스크톱 몫).
- CI: `if: false` 가드 제거. lint / test(x86_64 linux·windows + aarch64 macos, release
  리플레이 검증 포함) / cross-build(6타깃) 잡. `driftline-core`에 `f32`/`f64`가 없는지
  잡는 셸 가드 추가.
- 문서: M1 체크리스트에 평가 메모·결정·진행 상태 반영, DETERMINISM/TESTING/
  CONTRIBUTING/ARCHITECTURE/CLAUDE.md/README를 코드가 생긴 상태에 맞게 갱신.
- 미완: 저장소 위치 결정, 커밋(정책상 요청 시), CI 실제 통과(push 필요), 클라이언트
  육안 확인.
