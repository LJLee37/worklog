# 2026-09-01

## 작업

- 홈서버(raspi, Raspberry Pi 4 / Arch Linux ARM)에 연결한 저장장치들을 진단.
  - USB 메모리 3개(8/16/32GB) 내용물 확인: 32GB는 완전히 비어 있어 재사용 가능,
    8GB는 Ubuntu 설치 미디어, 16GB는 Tails + LUKS(불필요 확인).
  - 외장 HDD/SSD를 하나씩 갈아끼우며 SMART + badblocks 전체 읽기(비파괴) 스캔:
    - 1TB 도시바 2.5" HDD: SMART에 재할당/대기 섹터·비정정 오류 다수 →
      사용 보류(폐기 대상).
    - 320GB 삼성 3.5" HDD: badblocks 0, SMART 클린. 노후하지만 정상.
    - 128GB 샌디스크 SSD(Z400s): 정상, 수명 약 91% 잔여.
    - 128GB 샌디스크 SSD(X400): 호스트 쓰기량이 TBW 정격의 10배 이상, 스캔 중
      실시간으로 불량 블록이 증가 → 수명 말기, 데이터 용도 부적합.
    - 2TB 씨게이트 IronWolf HDD: 롱 셀프테스트 "완료(오류 없음)", SMART 클린.
      노후(가동 5년+)라 이중화/백업 역할로 권장.
  - smartmontools 일회성 설치와 스캔을 위해, 실행 범위를 좁힌(smartctl /
    badblocks / 해당 pacman 설치만) NOPASSWD sudoers 드롭인을 두고 systemd
    transient 타이머로 수 시간 뒤 자동 삭제되도록 셋업. 조기 삭제용 cleanup
    스크립트도 배치.
- zram(압축 RAM 스왑) 도입.
  - 배경: 디스크/USB를 스왑으로 쓰는 안을 검토했으나 플래시 수명·USB 브리지
    리셋·스왑 무결성 문제로 기각하고 zram으로 결정.
  - server-automation(Ansible) 저장소에 roles/zram 신규 작성:
    systemd-zram-generator 설정과 vm sysctl 드롭인(swappiness, page-cluster)을
    배포하고, daemon-reload -> 셋업 유닛 재기동 핸들러로 즉시 반영. 인벤토리
    그룹 + 플레이북 role 라인 + 노드별 host_vars 튜닝(raspi: 크기=RAM 전체·
    swappiness 180·lzo-rle / 메인 서버: RAM/4·상한 8GiB·swappiness 60)까지 포함.
  - raspi에 우선 적용. 저장소를 다른 작업(vault 갱신)에 쓰고 있어 그 변경을
    먼저 커밋·푸시로 정리한 뒤 진행. 전체 플레이북을 raspi에 돌리면 같은 노드의
    다른 role이 런타임에 학습한 설정을 덮어쓰는 문제가 있어, zram role만 실행하는
    저장소 밖 일회용 playbook으로 격리 적용.
  - 배포 중 버그 2건 수정: (1) 핸들러를 block으로 감싸 notify 대상 이름이
    등록되지 않던 문제 -> 평평한 핸들러로 분리, (2) 이 커널의 zram이 lzo/lzo-rle만
    지원해 zstd 지정이 조용히 무시되던 문제 -> 압축 알고리즘을 조건부 출력하고
    raspi는 lzo-rle 명시. 저장소 밖 playbook이라 host_vars가 안 잡혀 기본값이
    배포된 것도 함께 수정.
  - 결과: raspi에 /dev/zram0(크기 = 물리 RAM 전체, lzo-rle, 우선순위 100,
    vm.swappiness 180) 활성화, 재부팅에도 유지되는 구성. 메인 서버 몫은
    role/그룹/예시 host_vars에 준비만 해 둠(현재 Ansible 대상 아님).
