- 이력서 저장소의 사실 기록에 서버 세 대 적용 확인과, FIDO2 보안 키를 CA로 한 SSH 사용자 인증서와 호스트 키 인증서 운영을 추가함. 구현은 AI, 설계 검토 두 건과 서명은 본인으로 나눠 적음. 다른 작업 브랜치들이 같은 파일의 근처를 고치고 있어, 겹치지 않는 줄만 고치고 임시 복제본에서 다섯 브랜치와 병합을 시험해 충돌이 없는 것을 확인함.
- 이후 PR을 merge함. 이력서 저장소에는 제출용 원고가 사실 기록과 어긋난 곳(AI가 한 일을 본인 성과로 쓴 문장, 늘어난 role 수)을 TODO로 남기고, GitHub 프로필의 낡은 표기(옛 서명 키, 회사 칸)는 직접 지움.

## 작업

- 이력서 저장소: 한 지원처(클라우드와 컨테이너 운영 신입 직무)에 지원서를 제출했다. 공고와 양식 문항을
  원문 보관소에 남기고 활동사항과 자기소개서 두 문항을 썼다. 활동사항 칸은 입력 결과가 잘린 위치로
  24자 제한을 역산해 문구를 줄였다.
- 자기소개서에 쓸 근거로 개발 환경 설정 저장소의 셸 스크립트를 커밋 이력으로 확인했다. 2020~2023년
  스크립트는 모두 직접 짠 것이고, 컨테이너 이미지와 같은 문제(잦은 재설치)를 다른 방법으로 풀어 본
  결과라는 것을 사실 기록에 남겼다.
- 공고의 CI/CD와 컨테이너 오케스트레이션 요건에 맞는 근거가 있는지 GitHub 전 저장소를 다시 훑었다.
  새로 쓸 수 있는 근거는 없었다.
- 제출 본문에 키보드로 칠 수 없는 기호(가운뎃점, 긴 줄표 등)를 쓰지 않는 규칙을 이력서 저장소 작성
  가이드에 넣고, 전역 지침에도 넣도록 컨트롤 노드 인계 파일을 썼다(반영은 컨트롤 노드 세션).
- 다른 AI 서비스로 고쳐 쓴 판을 원래 판과 대조해 사실이 바뀐 곳과 주장이 세진 곳을 찾았다. 그 판은
  쓰지 않았다.
- 제출 화면을 받아 제출본을 보관하고, 변경을 두 커밋으로 나눠 PR로 올렸다.

## AI 활용

- Claude Code(Opus 5, 도중에 Opus 5.5로 전환)로 공고 조사, 사실 기록 대조, 초안 작성, 글자수 계산,
  제출본 대조를 진행했다.
- 유용했던 점: 커밋 이력에서 스크립트를 쓴 시점과 작성자를 확인해, 기억에만 있던 작업을 근거로
  쓸 수 있게 했다. 입력 칸이 잘린 위치로 글자수 제한을 역산해 칸에 맞췄다.
- 판단은 직접 했다. 이전 팀 활동의 표기 방식, 뺄 문단, 기호 규칙, 금지 문장을 직접 정했고 지원동기는
  마지막에 직접 고쳐 썼다.
- 아쉬웠던 점: AI가 초안에 지원처의 배포 빈도를 모르면서 "매일 배포하는 환경"이라고 지어 넣었고, 직접
  짚어서 뺐다. 이름만 들어 본 기술을 "개념을 안다"로 옮겨 적었다가 바로잡기도 했다. AI 초안의 같은
  뼈대 상투 문장이 여러 지원서에 되풀이된 것도 직접 발견해 금지 목록에 넣었다.

*(GitHub Actions 사용량 알림 조사와 driftline CI 분리 세션)*

## 작업
- GitHub Actions 저장 용량 90% 알림(0.45GB / 0.5GB) 원인 조사: 계정 저장소 112개 전수조사(아티팩트, 캐시, 워크플로, 9월 실행 기록). 원인은 driftline CI가 푸시마다 6개 타깃 실행 파일을 14일 보관 아티팩트로 올린 것(9/2~9/4 사이 16회, 96개, 약 784MB, 한도의 약 73%). 16회 중 10회는 문서 커밋이었음. 나머지 약 18%는 결제 API 권한이 없어 확인 보류.
- driftline CI를 둘로 나눔: 리눅스(x86_64, aarch64)는 개발 서버의 로컬 CI 스크립트와 pre-push 훅이 맡고(fmt, 6개 타깃 clippy, 결정론 가드, 테스트, 리플레이 골든 해시), GitHub에서는 윈도우와 macOS만 돌림. 문서만 바뀐 푸시는 건너뛰고, 나머지 타깃 빌드는 마일스톤 태그와 수동 실행에서만.
- 렌더 확인용 Windows 빌드는 1일 보관 아티팩트로 올리고, 개발 서버가 받은 뒤 바로 GitHub에서 지우는 스크립트 추가. 실제 푸시로 받기와 삭제까지 확인.
- cargo-deny로 의존성 라이선스(허용 목록), 보안 권고, 출처 검사를 로컬 CI에 추가. 현재 의존성은 모두 허용 라이선스이고, 관리 중단 알림 1건(winit 간접 의존)은 이유를 적어 예외 처리.
- aarch64 크로스 링커 설치를 server-automation 역할에 추가하고 컨트롤 노드용 인계 문서 작성(커밋과 적용은 아직 안 함).
- 라즈베리파이는 메인 서버 페일오버 전용으로 두고 CI와 크로스 빌드 도구를 설치하지 않기로 결정(추정 약 11GB로 SD 카드에 부담). aarch64 테스트는 메인 서버에서 qemu로 돌림. 이 결정을 컨트롤 노드 인계 문서에 추가.

## AI 활용
- Claude Code가 gh API로 저장소 전수조사를 하고, 잡 로그에서 아티팩트 실제 크기를 뽑아 GB-시간을 계산해 알림 수치와 대조함.
- 같은 세션에서 CI 분리 설계, 스크립트와 워크플로 작성, 훅 동작을 버리는 worktree에서 5가지 경우로 시험, 실제 푸시와 GitHub 실행으로 끝까지 검증.
- 실수: 훅 시험 때 worktree가 본 저장소의 빌드 캐시를 같이 쓰게 해서, 사라진 경로를 기억한 테스트 바이너리가 재사용돼 첫 푸시가 훅에서 막힘. 소스 수정 시각을 갱신해 다시 빌드하게 하고 해결.
