## 작업

### tick 길이 재결정 — 이번엔 입력 지연 기준으로

- 전날 남겨 둔 "1배속 입력 지연은 검증되지 않은 가정" 항목을 결론으로 옮겼다.
  **1 tick = 인게임 1/16초(62.5 ms).** 명령이 tick 경계에 붙으므로 tick 길이가 곧 "키가
  움직이기 시작하기까지의 최악 지연"인데, 0.5초면 500 ms다. 무거운 배가 아니라 굼뜬
  프로그램으로 읽힌다. 62.5 ms는 차량 조작이 즉각으로 느껴지는 구간 안이다.
  물리 서브스텝은 4 → 2회로 줄였다 — tick이 곱아지면서 필요가 없어졌다.
- **밀리초 헬퍼를 마이크로초로 바꿨다.** 62.5는 정수 밀리초가 아니라서, 그대로 뒀으면
  클라이언트 시계가 **0.8% 느리게** 흘렀을 것이다. 어떤 테스트도 잡지 못하고 긴 세션마다
  드러날 드리프트였다.
- **시스템별 주기(cadence)를 스케줄에 넣었다.** 고운 tick이 콜로니 연산량을 끌어올리지
  않게 하는 장치다 — 조타만 매 tick 돌고 느린 시스템은 주기를 받는다. 주기도 결정론
  계약의 일부라 이름과 함께 노출해 테스트가 고정한다. 시스템이 하나뿐인 지금이 넣기에
  가장 싼 시점이었다.
- 달력 시간을 물리 시간에서 떼어 tick만 곱게 하는 안은 **기각**했다. 그러면 "몇 시간
  항해했으니 몇 km"가 어긋나 시계가 속도계와 거짓말을 하는데, 항해가 곧 속도의 적분인
  이 게임에서는 그 어긋남이 정면으로 보인다. 압축을 달력과 물리에 같이 걸면 그 문제가
  없고, 지연은 tick을 곱게 해서 풀면 된다.
- 덤으로 1/16초와 1/32초는 2의 거듭제곱이라 고정소수점에서 **정확히** 표현된다. 적분기의
  시간 간격에 반올림 잔차가 없다는 뜻이고, 이건 고르고 나서 알게 된 것이다.
- 리플레이 픽스처를 새 tick률로 다시 굽고, 테스트·린터·6타깃 점검을 다시 돌렸다.
  푸시 후 CI 10개 잡 전부 통과.

### 설계 문서 확장

- **견시 절 신설**: 경보가 성립하려면 배가 위험을 알아야 하는데 그 앎이 공짜가 아니라는
  것을 규칙으로 세웠다. 탐지 세 경로(견시·해도·수심 측정), 탐지 거리를 정하는 것들
  (밝기·안개·견시 위치의 높이·폰의 특성과 니즈), 오탐과 놓침은 난수 없이 결정론적으로
  유도. 이미 있던 시스템 넷을 하나로 묶는 고리가 됐다.
- **조타 권한 확장**: 위임과 직접 조타를 평시든 경보 중이든 원할 때 오갈 수 있게 하고,
  경보 방침을 "인계 / 위임 유지" 둘로 뒀다. AI 항해사가 플레이어와 **같은 조작 표면**을
  쓴다는 제약을 명시했다 — 그래야 AI가 사람은 못 하는 회피를 하지 못하고, 인계와 재위임이
  매끄럽고, "실력이 곧 조작"이라는 기둥이 폰에게도 적용된다.
- **줄 끊기**: 돛의 줄은 무엇을 끊느냐에 따라 결과가 다르다는 것을 조사해 표로 넣었다.
  아딧줄을 끊으면 돛은 올라간 채 힘만 빠지고(펄럭이며 스스로 찢어진다), 마룻줄을 끊으면
  돛이 떨어지고, 활대 조종줄은 통제 상실에 가깝고, 버팀줄은 돛대가 부러진다. 전부 대가가
  있는 지름길이라 "인원이 부족한 배는 폭풍에서 더 비싸게 산다"가 계산 결과로 나온다.
  계류삭·예인삭 같은 연결의 줄은 경로 그래프의 간선을 지우는 것으로 따로 다뤘다.
- **구명보트**: "배가 배를 싣는다"가 편의 기능이 아니라 상태 모델 변경이라는 것을 절로
  분리해 명시했다. 적재 시 복원성 기여, 진수 후 독립 강체, 두 배 사이 승무원 이동까지
  걸린다. 쉬운 추가로 잡아 두면 나중에 아플 부류라 미리 적었다.
- 문서 절 번호가 밀리면서 저장소 전체의 교차 참조를 맞췄다.

## 작업

- 라즈베리파이(raspi)에 USB로 연결한 HP 컬러 레이저젯 프린터를 CUPS+Avahi로 홈 LAN과 VPN
  클라이언트 대역에 네트워크 프린터로 공유하는 Ansible role(`roles/printer`)을 신규 작성해
  배포. 실기기에서 큐 생성 후 아이폰·Windows에서 인쇄 확인.
- strongSwan VPN(IKEv2, 세 노드가 공유하는 role)에 접속한 클라이언트가 서버 자기 자신
  IP에만 닿고 같은 서브넷의 다른 호스트나 인터넷으로는 못 나가던 문제를 조사. 원인은
  서버가 IP 포워딩·NAT·방화벽 forward 규칙을 전혀 갖추지 않았던 것(원래 VPN이 "서버
  자신에게만 접속"하는 용도로만 쓰여 그동안 드러나지 않았던 구조적 문제)이었고, 임시
  규칙으로 즉석 검증한 뒤 Ansible role에 sysctl 드롭인 + nftables forward/NAT 규칙으로
  영구화. 실기기(아이폰·Windows·라즈베리파이 자체)로 재현·검증까지 마쳤다.
- 위 두 변경을 관심사별 커밋 2개로 나눠 커밋·푸시.
- 후속으로, VPN 접속 상태에서 프린터가 mDNS(Bonjour) 자동탐색으로는 안 잡히는 걸 확인 —
  멀티캐스트가 서브넷 경계를 못 넘는 구조적 한계(앞서 고친 유니캐스트 포워딩과는 별개
  문제)로 진단하고, IP 직접 지정으로 우회하는 방법을 안내. 근본 해결(VPN을 route-based
  방식으로 전환)은 배보다 배꼽이 커 보류하기로 함.

  2개 커밋으로 정리했다.
- 마지막 "VPN 중 프린터가 안 잡힌다"는 질문에는 되는 척 얼버무리지 않고 mDNS/멀티캐스트의
  근본 한계를 짚고, 더 큰 변경(VPN 방식 전환)의 스코프를 분명히 선 긋고 판단을 사용자에게
  넘겼다.

## 작업

- 다른 프로젝트 하나에서 시험삼아 "병렬로 처리 가능한 건 병렬로" 한 번 시켜봤더니,
  토큰 비용은 더 들었지만 속도·정확도·효율이 모두 나았다. 한 번의 결과이긴 하지만
  방침으로 굳혀 볼 만하다고 판단해, `server-automation`의 `agentic_coding` role
  템플릿(전역 CLAUDE.md를 렌더링하는 원본)에 "작업 오케스트레이션 (복잡도 판단 ·
  병렬 처리)" 섹션을 신설했다.
- 규칙의 골자: 작업을 받으면 바로 착수하지 말고 **복잡도 판단 → 병렬화 가능성 검토 →
  계획 제시 → 승인 → 실행** 순서를 따른다. 병렬 가능하면 서브태스크 목록·모델·의존
  관계·통합 방식을 제시해 승인받고 병렬 실행하고, 불가하면 이유를 밝히고 단일 에이전트
  순차 계획을 제시해 승인받는다.
- Claude Code의 기본 동작은 "사용자가 명시적으로 요청하지 않으면 서브에이전트를 쓰지
  않는다"인데, CLAUDE.md의 지시는 그 예외로 인정된다는 점을 확인하고 그 사실을 지침
  본문에 명시했다. 이 한 줄이 없으면 문서를 써 놔도 규칙이 실제로 발동하지 않는다.
- 1차 초안에서는 "같은 파일을 동시에 쓰지 않는다"를 병렬화의 필수 조건으로 뒀는데,
  검토 후 그 조건을 걷어냈다. git merge로 합칠 수 있으면 worktree로 격리해 병렬
  편집하고, 순차 실행은 병합이 어려운 경우(파일 전체를 겹쳐 재작성, 자동 생성 파일,
  바이너리, 서로의 결과를 봐야 다음 편집을 정할 수 있는 경우)로만 한정하도록 뒤집었다.
  파일 충돌을 회피 대상이 아니라 관리 대상으로 본 셈이다.
- worktree 항목에는 통합 절차(브랜치 순차 merge → 충돌 해소 → 통합 결과 재검증)와,
  git stash 스택이 worktree 간에 공유된다는 함정(병렬 작업 중 stash 금지, 임시 커밋으로
  대체)을 같이 적었다.
- 서브태스크 모델 지정 규칙도 문서화했다: 기본은 성격에 맞춰 자율 선택(넓은 검색·단순
  요약은 경량 모델, 설계·까다로운 디버깅은 고성능 모델), 사용자가 지정하면 그 지정이
  우선, 자주 쓰는 조합은 에이전트 정의 파일의 frontmatter로 고정, 컨텍스트를 그대로
  물려받는 fork형 서브에이전트는 항상 부모와 같은 모델이라 지정이 무시된다.
- 템플릿 Jinja2 파싱과 플레이북 syntax-check로 검증한 뒤 커밋하고 master에 푸시했다.
  worktree에 체크아웃된 브랜치라 master를 직접 체크아웃할 수 없어 `HEAD:master` 형태로
  밀었다.
- 실제 배포(플레이북 실행)는 sudo가 패스워드를 요구해 비대화식으로 돌릴 수 없어,
  사용자가 직접 실행하는 것으로 분담했다.

## AI 활용

- Claude Code(Opus 5)로 진행. "이 방침을 전역 지침에 넣어라"라는 요구를 받아 문서 초안,
  검증, 커밋·푸시를 맡겼고, 규칙의 강도(파일 충돌을 병렬화 차단 조건으로 볼지)는 직접
  결정해 되돌렸다.
- 유용했던 지점:
  - "CLAUDE.md의 지시가 기본 서브에이전트 금지 동작의 예외로 인정된다"는, 문서를 써도
    실제로 작동할지를 가르는 조건을 짚어 지침 본문에 못 박은 것.
  - 서브에이전트 모델 지정이 가능하냐고 물었을 때 자율 선택/사용자 지정/정의 파일 고정
    세 경로와, fork형은 지정이 무시된다는 예외까지 구분해 답한 것.
  - 배포 방법을 정하기 전에 sudo가 패스워드를 요구한다는 사실을 먼저 확인해, 못 하는
    일을 시도하는 대신 사용자 실행으로 넘긴 것.

  적어 둔 게 원인이다.
