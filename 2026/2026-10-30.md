## 작업

- 여러 코딩 에이전트를 터미널에서 함께 돌리는 herdr 를 찾아 지금 쓰는 Orca 와 비교함. herdr 는 지금 세 가지(원조인 터미널판 TUI v0.9.5, 10-16 에 나온 데스크톱 앱과 그 서버 herdr-core, 모두 Apache-2.0)이고, 비교는 TUI 기준으로 함
- main-server 에서 Orca 의 구성을 확인함: Windows 앱이 SSH 터널 안으로 붙고, 서버에는 데몬과 상태 저장소, Claude Code 훅 13개와 상태줄이 있음. 텍스트 설정 파일은 없고 설정은 앱과 SQLite 에 있음
- 정리한 차이: herdr 는 시스템 OpenSSH 로 붙어 인증서를 그대로 쓸 수 있으므로, Orca 때문에 세운 터널이 원리상 필요 없음. 대신 diff 리뷰, GitHub 연동, 내장 브라우저, 모바일 앱이 없음. 설정이 TOML 파일 하나라 dotfiles 로 관리하기 쉬움
- 조사 결과 중 SSH 접속 방식의 차이를 개인 위키에 자료 둘(Orca 터널 문서 발췌, herdr 의 원격 접속 문서)로 넣음
- main-server 에 공식 설치 스크립트로 v0.9.5 를 시험 설치함. 스크립트를 먼저 읽고, 판 정보, GitHub 릴리스, 깔린 파일의 해시가 같은지 확인함. 사용자가 써 보고 잘 된다고 확인함
- 인앱 알림을 조사함: 크기는 설정이 없고, 소리는 클라이언트에서 나므로 SSH 방식에서는 들리지 않음. Windows 클라이언트 방식이 해결책이고 시험하지 않음
- agentic_coding role 에 herdr 설치 태스크를 더하는 패치와 인계 문서를 만듦(두 노드, 플레이북마다 공개 최신판에 맞춤). 설치, 올림, 실패 경로를 시험 플레이북으로 확인함. 적용은 11-04 컨트롤 노드 세션에서 끝남

## AI 활용

- Claude Code(Opus 5.5)로 조사와 패치 작성을 함. 웹 문서와 GitHub API, 이 노드의 파일을 읽어 비교표와 설정 정리를 만듦. 서브에이전트는 쓰지 않음
- 유용했던 점: 검색 결과의 "AGPL" 이 포크 하나의 이야기이고 지금은 Apache-2.0 임을 GitHub API 로 바로잡음. 저장소 이름이 바뀐 것과 제품이 셋으로 갈린 것을 찾아 비교 대상을 TUI 로 좁힘
- 아쉬운 점: 패치의 register 이름이 스위치 변수와 겹쳤는데 시험에서 못 잡았고, 적용하는 세션이 찾아 고침
