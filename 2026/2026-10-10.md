# 2026-10-10

*(컨트롤 노드: 코딩 도구 변경 적용과 정리)*

## 작업

- 자정 무렵 컨트롤 노드(USB 로 부팅하는 노트북)를 다시 세우고 최신으로 맞추는 스크립트를 개인 설정 저장소에 올렸다. 컨트롤 노드는 일부러 Ansible 인벤토리 밖에 두어 그 기기에만 사는 설정이 문서 여러 곳과 손편집에 흩어져 있었다. 도구 설치, 저장소 clone, 커밋 서명 설정, SSH 인증서 설정, 덮개 설정, mod 등록을 한 스크립트로 묶었고, 점검 모드로 이 기기에서 돌려 실제 상태와 맞는 것을 확인했다.
- 노드별 설정 예시 파일을 실제 파일의 키와 비밀이 아닌 값에 맞췄다. 예시를 복사해 다시 채우면 실제에만 있던 키(메신저 채널, 프린터 큐)가 조용히 빠지던 문제다. 메신저 채널 값이 비밀값 저장소에 있다고 기억했는데, 값을 출력하지 않고 키 이름만 비교하는 스크립트로 확인하니 실제 설정 파일에만 있었다. 커밋 전에 예시에 들어간 실제 값을 목록으로 보여 주고 승인받았다.
- 사용량 상태줄 mod, 노드의 claude 두 벌 맞춤, 쓰지 않는 코딩 도구 제외를 두 노드에 적용했다. 적용 전에 관련 세션 셋에 물어 진행 중인 일이 없는 것을 확인했고, 점검 결과를 비밀값을 가린 사본으로 검토했다. 적용 뒤 두 노드의 claude 세 경로가 같은 버전이 됐고 mod 가 켜졌으며, 비서 게이트웨이는 다시 떠서 명령 72개를 맞췄고 대기 노드의 게이트웨이는 꺼진 그대로였다.
- 아침 브리핑과 같은 PATH 로 claude 를 한 번 돌려 보니 대기 노드만 인증에 실패했다. 대기 노드는 claude 를 거의 부르지 않아 로그인 갱신 토큰이 이틀 전에 이미 만료돼 있었다. 사용자가 다시 로그인했고, 다음 만료 전에 갱신하는 할 일을 장부에 넣었다.
- 끝난 인계 파일 넷을 각 세션과 협의해 지웠고, 그 파일을 가리키던 TODO 문장과 끝난 구독 관찰 항목을 정리했다. 메인 서버 세션이 남긴 mod 관련 실측과 주의점을 문서에 보충하는 커밋을 받아 만들었다.

## AI 활용

- Claude Code(Opus 5.5)로 진행했다. 적용 시각과 범위는 장부 작업 세션, 메인 서버 비서 세션, mod 세션과 원격 메시지로 맞췄다.
- 좋았던 점: 적용 뒤 아침 브리핑과 같은 조건으로 한 번 더 돌려, 평소에는 드러나지 않는 대기 노드의 로그인 만료를 다음 장애 전에 찾았다. 비밀값 저장소는 값 없이 키 이름만 비교했다.
- 아쉬웠던 점: 컨트롤 노드 스크립트의 첫 점검이 경로 표기만 다른 같은 설정을 "필요" 로 표시해, 비교 방식을 고친 뒤 커밋했다. 적용 결과에서 대기 노드의 게이트웨이 재시작 표시를 보고 켜졌는지부터 의심했는데, 꺼진 서비스는 켜지 않는 재시작이었다.

*(메인 서버: 사용량 상태줄 mod 적용 확인과 정리)*

## 작업

- 컨트롤 노드가 사용량 상태줄 mod 와 claude 두 벌 맞춤을 적용하기 전에, 실제 Claude Code 설정 파일의 사본으로 플러그인 등록과 설치를 돌려 기존 설정이 그대로 남는지 확인했다. 더해지는 키는 둘뿐이었다. 사본에서는 모델 설정 값이 바뀌었는데, 시험용 설정 폴더에 마이그레이션 기록이 없어서 생긴 일임을 확인하고 적용에 동의했다. 적용 뒤 실제 값은 그대로였다.
- 적용 결과를 이 노드에서 직접 확인했다. 세 경로의 claude 가 같은 버전이 됐고, mod 가 켜졌고, 설정 파일은 보존됐다.
- 세션 간 캐시 공유가 실제로 되는지 실험했다. 별도 tmux 소켓에서 대화형 세션 둘을 띄우고 6분 동안 저장소 파일과 세션별 디버그 로그를 봤다. 두 세션의 엔드포인트 호출은 0건이었고 머신 전체 호출은 2분에 한 번이었으며, 실행 중인 세션이 다른 세션이 받은 값을 읽어 갱신하는 것도 확인했다. 첫 시도는 홈 폴더의 작업 공간 신뢰 확인에 막혀, 신뢰를 대신 수락하지 않고 이미 신뢰된 폴더에서 다시 돌렸다.
- 끝난 인계를 컨트롤 노드 세션과 협의해 정리했다. 인계 파일은 그쪽이 지웠고, 이쪽 저장소 사본의 커밋하지 않은 같은 변경은 백업해 원격과 대조한 뒤 되돌리고 최신을 받았다. 차이는 원격 커밋이 의도적으로 바꾼 두 곳뿐이라 백업과 개발용 사본을 지웠다.
- 이 세션에만 남아 있던 사실(캐시 공유 실측, mod 를 고칠 때 걸리는 것, 배포 태스크를 실제 설정 없이 시험하는 법)을 저장소 문서에 보충하는 변경을 만들어 컨트롤 노드에 넘겼다. 시험에 쓴 임시 파일과 더 쓰지 않는 플러그인 저장소 파일은 지웠다.

## AI 활용

- Claude Code(Opus 5.5)로 진행했다. 컨트롤 노드 세션과 원격 메시지로 적용 동의, 정리 범위, 문서 보충, 작업로그를 주고받았다.
- 좋았던 점: 적용 전 점검을 실제 설정의 사본으로 해서 설정 파일이 보존되는 것을 미리 확인했다. 캐시 공유를 추정으로 두지 않고 세션별 호출 수로 실측했다.
- 아쉬웠던 점: 실험 세션의 작업 폴더가 신뢰됐는지 먼저 확인하지 않아 첫 실험을 버렸다.
