## 작업
- 녹음 파일 전사에 쓸 그래픽카드(GTX 1660 Ti)를 주 노드에 닮
  - 끄기 전에 주 노드의 Claude Code 세션 8개에 마칠 일이 있는지 묻고, 노드에만 있던 인계 문서를 컨트롤 노드로 복사함. 꺼진 동안 대기 노드가 비서를 넘겨받았고(상태 손실 없음), 부팅 뒤 주 노드가 다시 돌려받음
  - 준비하며 랜카드 이름이 그래픽카드 유무에 따라 바뀌는 것을 찾음. 11-06 에 옛 카드를 뺀 뒤부터 이름이 달라져 VPN 의 주소 변환 규칙이 맞지 않았음. 새 카드를 같은 슬롯에 꽂자 예상대로 이름이 돌아옴. 이름을 MAC 으로 고정하는 것은 보류(사용자 결정)
  - 드라이버를 설정 role 로 깔고, 드라이버나 커널이 오르면 재부팅이 필요하다고 패키지 관리자가 알리게 함. 사용자 결정으로 짧은 재부팅은 비서 넘김 없이 하기로 하고, 재부팅 뒤 콘솔 화면과 모니터를 나중에 꽂는 경우를 확인함

- 커널을 올린 뒤 재부팅 전에도 모듈을 올릴 수 있게 kernel-modules-hook 을 깔게 함. 처음에는 돌고 있는 커널로 판단해 빠지는 경우가 있어 깔린 커널로 판단하게 고침
- Ghostty 로 노드에 붙을 때 화면이 깨지지 않게 노드에 Ghostty 의 terminfo 를 깔고, 모르는 TERM 은 xterm-256color 로 낮추게 함
- herdr 의 Claude 통합을 노드와 컨트롤 노드에 깜. 적용이 비서 설정을 되돌려 비서 게이트웨이가 다시 시작됐는데, herdr 화면에서 켠 비서 통합이 비서 설정에 들어가 있었기 때문. 사용자 결정으로 비서 통합은 지움
- 그동안 쓰던 원격 세션 앱(Orca)을 은퇴시킴: 노드의 SSH 키, 비서의 상태 플러그인, 문서를 지우고 적용(실패 0). Windows 쪽 정리는 사용자
- 저녁에는 herdr 설정을 노드 role 로 옮기고, 모든 노드가 사용자 인증서를 믿게 하며, 인증서가 끊겼을 때 노드에서 쓸 비상 발급 도구를 두는 변경을 만듦(적용은 11-17)
- 설정 저장소(컨트롤 노드): SSH 안에서 복사한 것이 컨트롤 노드 클립보드에 닿게 Ghostty 와 herdr 원격 모드를 맞추고, 기본 편집기를 nvim 으로, 터미널 앱을 띄우는 터미널을 Ghostty 로 둠. 설치 스크립트가 기기마다 다른 값을 설치할 때 받게 바꿈

## AI 활용
- Claude Code(Opus 5.5) 컨트롤 노드 세션이 주 노드 세션들에 Remote Control 로 전원 내림을 알리고 답을 모아 표로 정리함. 답이 없는 세션은 "없음"이 아니라 "미응답"으로 따로 적음
- 드라이버 role, 위키, 훅, terminfo, herdr 변경은 Claude 가 작업 브랜치에 쓰고, 서명(하드웨어 키)과 점검, 적용은 사용자가 자기 터미널에서 실행함. 적용 기록은 비밀값을 가린 발췌로만 읽음
- 다른 컨트롤 노드 세션이 설치 USB 스크립트를 쓰고, 사용자가 sudo 로 실행한 기록을 읽어 검증함
