# 2026-10-05

*(10-01 개인 비서 모델 교체 결정의 적용과 비서 기능 확장)*

## 작업

- 개인 비서의 대화 모델을 10-01 에 정한 구독 방식의 새 모델로 바꿨다. 두 노드에서 각각 구독 계정으로 로그인하고 새 모델과 보조 모델이 실제로 불리는지 확인한 뒤, Ansible role 에 반영해 두 노드에 적용했다. 예비 모델은 다른 공급자의 가벼운 모델로, 대화 압축 상한은 거의 매 턴 압축이 돌던 문제를 풀도록 올렸다. 이미 등록된 예약 작업에도 새 모델이 들어가도록 작업 등록 스크립트에 기존 작업을 맞추는 모드를 더했다.
- 비서용으로 손으로 만든 스킬이 노드마다 따로 깔려 대기 노드에 옛 판이 남던 것을 고쳤다. 이제 role 이 두 노드에 같은 판을 깔고 고정한다.
- 비서가 개인 지식 볼트(Obsidian, git)를 읽고 고치게 했다. 대기 노드에도 볼트를 받아 두고, 고치기 전 pull, 볼트 검증기와 CI 와 같은 시각 검사, 충돌 때 멈추는 절차를 스킬로 적었다. 적용 직후 비서가 시즌 성과 기록을 직접 볼트에 올렸고 CI 를 통과했다.
- 즐겨 하는 모바일 게임에 대한 질문에 한국 서버 기준으로 답하게 했다. 한국 서버는 일본 서버를 몇 달 뒤 같은 순서로 따라가므로, 볼트의 기록과 시즌 번호 짝으로 앞으로의 일정을 추정하고 근거를 공지, 커뮤니티 예측, 직접 추정으로 나눈다. 공개 사용이 확인되지 않은 커뮤니티 사이트의 백엔드 API 는 새로 조회하지 않기로 했다.
- 볼트에 있는 그 게임의 콘텐츠 일정 기록 네 종류를 두 서버의 최신 정보로 갱신하고, 일본 서버 픽업 기록(서비스 시작부터 296줄), 한국 서버 픽업 기록(260줄), 한국 서버 일정 예측 노트를 새로 만들었다. 공식 공지, 위키, 공략 사이트를 서로 대조하고 출처를 노트마다 남겼다.
- 비서의 저녁 소식이 이틀 간격으로 같은 소식을 되풀이하던 원인(예약 작업이 바로 앞 실행 하나만 보여 줌)을 찾아, 최근 2주에 전한 소식을 사전 스크립트로 넣었다. 인격 설정에는 평가 때 다듬은 대화 길이 규칙과 "지킬 수단이 있을 때만 약속" 규칙을 넣었다.
- 태블릿 Obsidian 에서 새 노트가 내려오지 않던 원인을 찾았다. 쓰던 동기화 플러그인이 자기 메타데이터 파일로만 변경을 판단해, 다른 도구가 올린 노트를 받지 못했다(07-12 이후 추가된 96개 중 93개). 실제 git 커밋을 비교하는 플러그인으로 바꾸기로 하고 순서를 적어 두었다.
- 캘린더 기능은 할 일 장부에 일정과 미리 알림을 더하는 방향으로 정해 장부 저장소 세션에 인계했고, 두 세션이 원격 제어로 직접 계약을 맞추고 있다.
- 전환 일주일이 된 할 일 장부의 되돌리기 자료, 낡은 브랜치, 끝난 인계 문서를 정리하고, 저장소 밖에 있던 설계와 감사 문서를 각 저장소의 docs 로 옮겼다. 메인 서버 아침 브리핑이 사흘째 실패하던 원인(AI 도구 로그인 만료)을 찾아 다시 로그인했다. 하드 디스크를 옮긴 뒤 하루 평균 온도가 약 6도 낮아진 것을 확인했다.

## AI 활용

- Claude Code(Opus 5.5)로 진행했다. 조사와 기록 수집은 서브에이전트로 나눠 병렬로 돌렸다(비서 내부 구조, 장부 구조, 게임 일정 기록 네 종류, 픽업 기록 연도 구간 넷, 지난 세션의 끝나지 않은 지시 점검). 서명이 필요한 커밋은 작업 브랜치에 모아 세 번에 나눠 서명했다.
- 좋았던 점: 지난 세션 기록을 훑어 끝나지 않은 지시를 찾았고, 지울 예정이던 폴더 안에만 있던 미룬 개선 목록을 먼저 옮길 수 있었다. 볼트 검증기에서 비서가 예전에 검증 없이 올린 깨진 링크를 찾아 고쳤다.
- 아쉬웠던 점: 시험용 임시 설정으로 비서 코드를 돌렸다가 실제 실행 파일이 임시 경로를 가리키게 되어, 본인 명령이 실패한 뒤에야 고쳤다. 적용 전 점검 로그를 볼 때 비밀값 줄의 앞뒤 문맥을 가리지 않아 토큰과 키가 대화에 찍혔고, 둘 다 새로 발급해 바꿨다(비밀값 파일은 점검 로그에 내용이 남지 않게 고쳤다). 보류 브랜치로 바꿔 둔 채 점검이 돌아 다시 돌렸다(적용 스크립트가 master 에서만 돌게 고쳤다). AI 가 영어로 답한 적이 있어 한국어로 다시 요청했다.
- 본인이 먼저 짚은 것: AI 세션의 반복 점검 금지 규칙과 비서의 정기 갱신은 다르다는 점, 커뮤니티 사이트 API 의 공개 사용 여부, 일정 추정에 시즌 번호 짝을 그대로 써도 된다는 점(운영사가 순서를 그대로 따른다고 밝힘), 저녁 소식의 되풀이.
