- 첫 새 아침 브리핑의 일정 칸이 "불러오지 못했습니다"로 나간 것을 아침 브리핑 세션이 고침(비서 실행 환경에서 장부용 Python 지정). 사용자 승인으로 push 된 뒤 두 노드가 받았는지 확인함
- 비서 정비 보류를 걸 때 sudo 가 계속 거절된 원인을 찾음: 비밀번호를 세 번 틀려 pam_faillock 이 계정을 잠시 잠근 것이라 맞는 비밀번호도 거절됐고 su 는 됐음. 보류를 건 뒤 라즈베리파이가 인수한 것을 확인함
- 메인 노드가 한 번 재부팅된 뒤에도 보류와 라즈베리파이 주인이 유지된 것을 확인함

## AI 활용

- Claude Code(Opus 5.5) 컨트롤 노드 세션이 Remote Control 세션 간 메시지로 열세 세션에 알리고 답을 모음. Remote Control 이 꺼진 세션 하나는 전파가 닿지 않아 사용자에게 따로 알리고, 다른 세션을 거쳐 답을 받음
- sudo 가 필요한 단계는 사용자가 자기 터미널에서 짧은 명령으로 함
